# 7.3 — Observe the effective mirror Maven actually selects

## Goal
Prove **which repository endpoint and ID** Maven uses for the artifact that receives HTTP 401. The original repository declared in a POM (often `central`) may be replaced by a mirror before Maven selects authentication credentials.

| Question | Evidence | Expected for a single corporate Nexus mirror |
|---|---|---|
| Which original repository was targeted? | `Using mirror ... for central` | `central` (or another source repository) |
| Which mirror was selected? | Maven `-X` log | `company-nexus` |
| Which URL is contacted? | `Downloading from ...`, transfer error | Actual Nexus artifact endpoint |
| Which server ID is required? | Selected mirror ID | `<server><id>company-nexus</id>` |
| Is it authentication or TLS? | HTTP 401 vs SSL exception | A true HTTP 401 means an HTTP component responded |

## 1. Capture a bounded diagnostic log
Run from the same shell, project directory, and Maven invocation that fails:

```bash
mvn -X -e clean install > /tmp/maven-mirror-debug.log 2>&1
```

**Security:** debug logs may contain corporate URLs, proxy details, or sensitive headers. Do not publish them unchanged.

Extract relevant lines:

```bash
grep -Ein 'Using mirror|Downloading from|Downloaded from|Could not transfer|from/to|401|Unauthorized' \
  /tmp/maven-mirror-debug.log
```

Example *illustrative* output:

```text
[DEBUG] Using mirror company-nexus (https://nexus.company.com/repository/maven-public/) for central (https://repo.maven.apache.org/maven2/).
Downloading from company-nexus: https://nexus.company.com/repository/maven-public/org/example/lib/1.0/lib-1.0.pom
... status: 401 Unauthorized
```

This says Maven **selected `company-nexus`**, so matching `<server id="central">` alone is insufficient for this transfer.

## 2. Understand the selection chain

```text
POM / super POM / profiles
  repository id=central, url=https://repo.maven.apache.org/maven2/
      ↓ Maven mirror selection
settings.xml mirror id=company-nexus, mirrorOf=*, url=https://nexus.company.com/repository/maven-public/
      ↓ Maven credential selection
settings.xml server id=company-nexus
      ↓ HTTPS and HTTP authentication
Nexus artifact URL
```

Mirror matching determines the **selected repository endpoint**; server matching uses that endpoint's **ID**, not the URL's hostname.

## 3. Inspect the matching entries

```xml
<mirrors>
  <mirror>
    <id>company-nexus</id>
    <mirrorOf>*</mirrorOf>
    <url>https://nexus.company.com/repository/maven-public/</url>
  </mirror>
</mirrors>
<servers>
  <server>
    <id>company-nexus</id>
    <username>TOKEN_USERNAME</username>
    <password>ENCRYPTED_OR_PLAINTEXT_TOKEN_PASSWORD</password>
  </server>
</servers>
```

All values and URLs above are illustrative. The *literal* `*` matches eligible repositories; it is not a placeholder.

## 4. Distinguish transfers
An invocation of `mvn clean install` may retrieve **build plugins** before it retrieves project dependencies. Identify the **specific artifact filename** and the repository ID next to the 401 rather than presuming the failing transfer is a project dependency. `-U` can force additional remote checks but is not needed to establish the selected mirror; local cache can hide a transfer.

## 5. Common outcomes

| Observation | Likely meaning | Next action |
|---|---|---|
| Mirror ID A, server ID B | Credentials not matched to selected endpoint | Add or correct server A; see 7.4 |
| No mirror selected | `mirrorOf` excludes source, different settings, or logs incomplete | Inspect effective settings and profiles |
| Maven URL differs from tested curl URL | Tests do not establish equivalent access | Curl **exact failing artifact URL** |
| Correct ID and URL, still 401 | Possibly wrong token, encryption, proxy, redirect, or auth policy | Check 3, 8, and 9 |
| PKIX / SSL handshake error, not 401 | Java certificate validation or TLS issue | Check 5 |

## 6. Acceptance criterion
Record (a) source repository ID, (b) effective mirror ID, (c) exact artifact URL, (d) matching server ID, and (e) HTTP error. These five facts let you test the same request with curl.

## Cautions
- Debug line wording changes across Maven / Resolver versions.
- The log may not reveal the credentials sent; do **not** expect plaintext passwords in output.
- An HTTP 401 might be issued by a gateway, not Nexus itself.
